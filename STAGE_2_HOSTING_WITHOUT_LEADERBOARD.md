# STAGE_2_HOSTING_WITHOUT_LEADERBOARD.md

## 1. Outcome and hosting architecture

Deploy the Stage 1 game with no database, authentication service, Redis, KV, or cloud persistence. Progress and personal scores stay in the browser. Python remains authoritative for quantum calculations, but local records are explicitly unverified and unsuitable for a global competition.

Use one Vercel Hobby project: a Next.js static export served from the CDN and a FastAPI application for `/api/*`. Build the frontend into root `public/`, which Vercel's Python framework integration serves as static assets. This avoids depending on mixed Next.js/Python runtime auto-detection. [FastAPI on Vercel](https://vercel.com/docs/frameworks/backend/fastapi), [Next.js static export](https://nextjs.org/docs/app/guides/static-exports)

```text
Browser -> Vercel CDN -> exported Next.js pages/assets
Browser -> same-origin /api/run-circuit -> Python function -> Qiskit/Aer/Paulice
Browser -> localStorage -> tutorial state and personal results
```

Hobby is for personal non-commercial use, with quotas and possible interruption when allowances are exhausted. “Free” means no paid service is required within those allowances; it does not mean unlimited simulation capacity. [Vercel Hobby](https://vercel.com/docs/plans/hobby)

Use client components for localStorage, editing, and fetches. Do not introduce Next server actions, runtime route handlers, middleware-based authentication, or request-dependent server rendering in this deployment. Split charts and advanced state inspectors into lazy-loaded components. Use CSS/SVG animations rather than a large 3D engine. Keep fonts and icons local where practical; import only the Lucide icons actually used.

## 3. Python runtime and reproducible dependencies

Set `.python-version` to `3.12`. Vercel currently supports Python 3.12, 3.13, and 3.14; do not request Python 3.10 simply because it satisfies the minimum specification. [Python runtime](https://vercel.com/docs/functions/runtimes/python)

Use this initial `pyproject.toml`, then resolve and commit the exact lockfile:

```toml
[project]
name = "quantum-shield"
version = "0.1.0"
requires-python = ">=3.12,<3.13"
dependencies = [
  "qiskit>=2.5.2,<3",
  "qiskit-aer>=0.17.1,<1",
  "qiskit-paulice>=0.2.0,<1",
  "numpy>=1.26,<3",
  "fastapi>=0.117.1,<1",
  "pydantic>=2,<3",
  "uvicorn>=0.30,<1"
]

[dependency-groups]
dev = ["pytest>=8,<10", "httpx>=0.27,<1", "rich>=13", "ruff>=0.9"]

[tool.vercel]
entrypoint = "backend.app:app"

[tool.vercel.scripts]
build = "python scripts/build_web.py"
```

Qiskit 2.5.2 was the latest documented patch checked for this guide. Recheck stable releases before resolving, then test the resulting Qiskit/Aer/Paulice combination. Ranges above are resolver inputs, not a reproducibility guarantee. [Qiskit release notes](https://quantum.cloud.ibm.com/docs/en/api/qiskit/release-notes/2.5)

```powershell
python -m pip install uv
uv lock
uv sync --locked
uv run python -c "import qiskit, qiskit_aer, qiskit_paulice; from importlib.metadata import version; print({p: version(p) for p in ['qiskit','qiskit-aer','qiskit-paulice']})"
```

During implementation, migrate the existing root `requirements.txt` to the pyproject/lock workflow so deployment has one authoritative dependency definition. Keep terminal, notebook, PDF-reading, and plotting dependencies in development groups. Do not ship `pymupdf`, Jupyter, Matplotlib, GPU Aer, or IBM Runtime unless a measured runtime requirement justifies them. Compile no dependencies at request time.

Use CPU Linux wheels compatible with Vercel. A successful Windows import is not proof of Linux deployment compatibility. The first preview deployment must import all three quantum packages and execute an actual noisy checked circuit.

## 4. Build and Vercel configuration

`scripts/build_web.py`:

```python
from pathlib import Path
import shutil
import subprocess

ROOT = Path(__file__).resolve().parents[1]
WEB = ROOT / "web"
OUTPUT = ROOT / "public"

subprocess.run(["python", "scripts/export_levels.py"], cwd=ROOT, check=True)
npm = shutil.which("npm.cmd") or shutil.which("npm")
if npm is None:
    raise RuntimeError("Node.js/npm is required to build the frontend")
subprocess.run([npm, "ci"], cwd=WEB, check=True)
subprocess.run([npm, "run", "build"], cwd=WEB, check=True)
shutil.copytree(WEB / "out", OUTPUT, dirs_exist_ok=True)
if not (OUTPUT / "index.html").is_file():
    raise RuntimeError("Static export is missing index.html")
```

This expects a clean deployment workspace. `public/` is generated-only and must not be used for hand-authored files; authored assets live in `web/public/`. For local builds, use a clean generated output directory to avoid obsolete pages surviving route changes. `export_levels.py` serializes the Stage 1 registry's public fields and rejects private noise credentials or internal data.

`vercel.json`:

```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "framework": "fastapi",
  "cleanUrls": true,
  "functions": {
    "backend/app.py": {
      "maxDuration": 60,
      "excludeFiles": "{web/**,public/**,notebook/**,docs/**,tests/**,.venv/**,**/__pycache__/**,**/*.pdf,**/*.ipynb}"
    }
  }
}
```

Vercel serves `public/` through its CDN, so those files need not be copied into the Python function. Verify this split in build artifacts. Keep `quantum_engine/`, `game/levels.py` if imported, and runtime benchmark definitions in the function. Do not add a broad SPA catch-all that rewrites `/api/*` to HTML.

Current documented standard Python bundle size is 500 MB uncompressed; Hobby has 2 GB memory and up to 300 seconds under Fluid Compute. This guide intentionally sets a shorter 60-second function ceiling and a 45-second application budget. Avoid relying on larger-function beta features. Recheck limits at deployment. [Function limits](https://vercel.com/docs/functions/limitations)

## 5. API contract, bounds, and request lifecycle

The Stage 1 service provides `evaluate(request)`; the HTTP adapter validates transport and delegates to it. Define strict Pydantic models with `extra="forbid"`, finite numbers, enum modes, positive version IDs, unique targets, and registered variant IDs.

| Route | Behavior |
|---|---|
| `GET /api/health` | Small readiness response with engine/package versions; no secrets |
| `GET /api/levels` | Public registry with ETag and benchmark metadata |
| `POST /api/run-circuit` | Bounded practice/benchmark execution and Stage 1 result |
| `POST /api/preview-circuit` | Small sandbox previews, maximum 5 data qubits and 64 operations |

Example valid run body:

```json
{
  "schemaVersion": 1,
  "levelId": 1,
  "variantId": "bell-depth1-paulice-v1",
  "mode": "practice",
  "targetOrder": [0],
  "checkCount": 1,
  "manualCheckIds": []
}
```

Register this variant ID in Stage 1 before using the smoke test. Do not accept client-supplied noise probabilities, seeds, budgets, target states, or score values for benchmark runs.

Initial hard bounds: 5 data qubits, 3 ancillas, 8 total qubits, 256 compiled operations, 128 compiled depth, 32 observable settings, and 4096 shots per setting. These are starting limits to benchmark, not performance promises. Reject work that exceeds measured deployment capacity rather than timing out unpredictably. If a full comparison is expensive, run one independently reproducible configuration per request, sequentially from the browser.

Enforce a 16 KiB request body limit while streaming the body, not just by trusting `Content-Length`. Target responses under 128 KiB. Return counts and compact metrics, not all raw shots or a full joint density matrix. Complex amplitudes use `{re, im}` pairs.

Error envelope:

```json
{
  "error": {
    "code": "INVALID_CHECK",
    "message": "This check crosses a T gate with an X component.",
    "requestId": "a2c68acf-80a1-453c-a24d-b6f0337aa8d",
    "retryable": false
  }
}
```

Use 400 for malformed JSON, 413 for oversized bodies, 422 for invalid circuit/rules, 429 for admission limits, 503 when simulation is disabled/busy, and 504 for the application deadline. Do not convert simulation failures into a zero score. Client errors must not expose Python tracebacks.

Run CPU-bound work outside FastAPI's async event loop, with at most one active simulation per worker and bounded admission. A request cancellation or async timeout does not necessarily terminate native Aer work. Check the deadline between observable settings and bound each individual simulation; use the platform duration ceiling as the final stop. Do not launch background jobs that outlive a response.

## 6. Cold starts and cost control without a database

1. Import Qiskit/Aer/Paulice once per function process; do not initialize them per shot.
2. Set Aer parallel experiment/thread settings to one for the initial deployment, and configure BLAS/OpenMP threads before imports.
3. Cache at most 32 immutable references/check configurations per warm process with a bounded LRU. Include payload, noise, engine, compilation, and metric versions in keys.
4. Never depend on warm caches for correctness, locking, rate limits, or persistence.
5. Precompute tutorial fixtures with Qiskit and ship their provenance; interactive new circuits still execute on the server.
6. Debounce previews, disable duplicate Run clicks, and reuse exact cached frontend responses only for matching configuration hashes.
7. Use public CDN caching for level metadata and static assets; use `Cache-Control: no-store` for run responses.
8. Provide a `SIMULATION_ENABLED` kill switch and monitor Vercel usage. Use available platform firewall controls for abusive traffic.

Without shared persistence, per-process counters cannot enforce a global user quota across scaled instances. Browser cooldowns improve UX, not security. Stage 2 can bound each request and use platform controls, but cannot promise a database-backed global rate limit. Do not schedule keep-alive pings merely to hide cold starts.

## 7. Local persistence schema and migration

Use one key: `quantum-shield:progress:v1`. Store only compact progress and the best result for each benchmark/variant/protocol combination. Cap retained records at 100 and total serialized size at 100 KiB.

```typescript
import { z } from "zod";

const probability = z.number().finite().min(0).max(1);
export const ProgressSchema = z.object({
  schemaVersion: z.literal(1),
  tutorialVersion: z.literal(1),
  introStatus: z.enum(["not_started", "in_progress", "completed", "skipped"]),
  completedSteps: z.array(z.string().max(64)).max(20),
  unlockOverride: z.boolean(),
  completedLevels: z.array(z.number().int().min(1).max(6)).max(6),
  bestScores: z.array(z.object({
    benchmarkId: z.string().max(128),
    variantId: z.string().max(128),
    metricId: z.string().max(128),
    configurationHash: z.string().regex(/^[a-f0-9]{64}$/),
    score: z.number().int().min(0).max(1000),
    fidelity: probability,
    retention: probability,
    savedAt: z.string().datetime(),
    verification: z.literal("local-only"),
  })).max(100),
  updatedAt: z.string().datetime(),
}).strict();
export type SavedProgress = z.infer<typeof ProgressSchema>;
```

Create defaults with status `not_started`, false override, empty arrays, and the current ISO time. During hydration:

1. Render a neutral loading gate until storage is read; never read localStorage during SSR/build.
2. Read inside try/catch and reject a raw value larger than 100 KiB before parsing.
3. Parse JSON and validate the complete schema. Invalid records fall back to fresh progress with a visible nonfatal explanation.
4. Canonicalize skipped status to `unlockOverride=true`; deduplicate valid completed IDs and step names.
5. Store previous-version migrations as explicit pure functions. An unknown future schema must not be overwritten automatically; use in-memory defaults and explain the incompatible saved data.
6. Merge known tabs' progress on the `storage` event: union completion sets, preserve any unlock, and retain the best matching score. Re-read and merge immediately before a write.
7. Handle quota/security exceptions with “Progress is saved for this session only.” Gameplay continues in memory.

localStorage offers no transactional cross-tab updates, so retain the merged in-memory state and reconcile on focus. For explicit Reset Progress, warn that all open tabs should reload, clear the key, reset memory, and broadcast a reset event; reset must take precedence over union merging.

Save after tutorial milestones and successful runs, not every animation frame. Never persist bearer tokens in this progress object. Export/import progress as validated JSON, clearly labeled local-only. An imported or edited local score is never automatically eligible for Stage 3.

## 8. Environment variables and deployment procedure

Stage 2 needs no database secrets and no IBM Quantum token.

| Variable | Location | Value/purpose |
|---|---|---|
| `SIMULATION_ENABLED` | Server | `true`; emergency execution switch |
| `ENGINE_VERSION` | Server | `quantum-shield-engine-v1` |
| `APP_ENV` | Server | `preview` or `production` |
| `OMP_NUM_THREADS` | Server | `1` |
| `OPENBLAS_NUM_THREADS` | Server | `1` |
| `MKL_NUM_THREADS` | Server | `1` |
| `NEXT_PUBLIC_ENABLE_LEADERBOARD` | Build/client | `false` |

Implementation sequence:

1. Pass Stage 1 physics and UI tests; commit source and dependency locks.
2. Run `uv sync --locked`, `uv run python -m pytest tests`, and `npm --prefix web ci`.
3. Start `uv run uvicorn backend.app:app --reload --port 8000` locally. For UI development, configure a development-only Next rewrite to that origin, or use `vercel dev` for same-origin routing. The production static export contains no rewrite dependency.
4. Run `uv run python scripts/build_web.py`; inspect `public/index.html`, `public/intro.html`, and all six `public/play/*.html` files.
5. Import the repository into a Vercel Hobby project with repository root as Root Directory and FastAPI as framework. Confirm `backend.app:app` is the detected entrypoint rather than the existing terminal `main.py`.
6. Set preview variables. Let the pyproject build hook run; do not override it with a conflicting Next-only command. Confirm the build image supplies Node/npm and installs the committed Python lock.
7. Inspect deployed static assets and Python function size. Run preview API smoke tests and inspect package versions.
8. Verify direct visits and refreshes at `/`, `/intro`, `/levels`, and `/play/1`. Verify `/api/run-circuit` returns JSON rather than a static fallback.
9. Set production variables, deploy the same tested commit, and rerun smoke tests against production.
10. Record deployment URL, commit, resolved versions, bundle size, and measured cold/warm latency in `docs/deployment.md`.

## 9. Release verification and failure handling

Test malformed JSON, oversize bodies, invalid level IDs, unsupported gates, excessive budgets, timeout errors, missing optional fields, stale responses, and the kill switch. Ensure no database SDK or connection is imported by any Stage 2 code path.

Measure one cold request after a fresh deployment and at least ten warm requests for the largest supported case. Record results rather than claiming an unmeasured latency target. Initial goals: warm practice runs below 10 seconds and every accepted configuration below the 45-second application budget. Reduce supported workload or use versioned Qiskit-generated check catalogs if those goals fail; do not silently replace simulation with fabricated results.

Verify local progress across reloads, browser restarts, multiple tabs, blocked storage, corrupt JSON, unknown schema versions, and reset. Show that another browser starts fresh. Check offline behavior: intro text and previously cached results may remain available; new quantum runs require the API and must show an offline message.

If a bundle exceeds limits, remove unused runtime dependencies and artifacts, inspect native-wheel contents, and rebuild. If a native import fails, resolve Linux wheel compatibility before release. If static pages return 404, inspect exported filenames and clean-URL routing; preserve API routes. If quotas are exhausted, disable runs and retain explanatory pages until service recovers.

Stage 2 is complete when the live app passes routing, simulation, accessibility, storage, and error tests with no database configuration and no required paid service.
