# Quantum Shield

A Next.js / React game with a Qiskit 2 backend. Six Flight Schools teach quantum noise and coherent Pauli checks; ten main missions use locked payloads and localized spacetime checks. No account, database, paid API or quantum hardware is required.

Developed for the IITJ QFF'26 Hackathon by team Schrodinger's Hackers: Shreyansh Agarwal, Vihan Karnik, and Sarthak Sharma.

Team credits are available from **About the team** in the Mission control footer. Edit names, photo paths and optional social links in `src/lib/team.ts`. Initials appear until a photo is configured. `public/team/shreyansh.svg`, `vihan.svg` and `sarthak.svg` are initials placeholders, not portraits. For real photos, add `public/team/shreyansh.webp`, `vihan.webp`, and `sarthak.webp` (square 400×400 px, WebP or JPEG, ideally under 100 KB), then set each member's `photoPath` to `/team/<filename>`. JPEG `.jpg` paths work too. Next.js lazily loads and optimizes the 80 px circular thumbnails; missing photos fall back to initials. Leave unknown social URLs as `null`.

[Submission information](SUBMISSION_INFO.md) collects the official checklist, repository facts, dependency credits, evidence and planning prompts for the team's own report and recording.

The executed [level design and validation notebook](notebooks/level_design_and_validation.ipynb) covers Flight Schools 1–6 and Main Levels 1–10: Qiskit circuit diagrams, real propagation/invalid checks, noise, reference solutions, repeated scores/targets, generated P′, constrained search, cross-level plots and T-scorer crosschecks. It is supporting analysis, not the final team report. Every output is generated by the actual repository code.

Run it in a separate analysis environment (Python 3.10 was clean-install tested; use `bin/python` instead of `Scripts/python.exe` on Linux/macOS):

```powershell
python -m venv artifacts/notebook-env
artifacts/notebook-env/Scripts/python.exe -m pip install -r notebooks/requirements.txt
artifacts/notebook-env/Scripts/python.exe scripts/run_notebook.py
artifacts/notebook-env/Scripts/python.exe scripts/run_notebook.py --check-saved
```

The runner executes a real Jupyter kernel and rejects cell errors, unexecuted cells, stale source/cache fingerprints and score disagreements with the authoritative JSON and rounded level-validation table. Analysis takes roughly a minute locally with the included source-fingerprinted search cache. To regenerate the expensive cache, run `artifacts/notebook-env/Scripts/python.exe scripts/cache_level_searches.py` (the initial full search took about 6.5 minutes), then rerun the notebook. Cached optima are finite-family best-found results and are freshly rescored, not global optimum claims. This does not recalibrate levels. Notebook/Jupyter/drawing requirements remain separate from the deployed Python requirements; existing Vercel exclusions are unchanged.

## Local setup

The live game was independently checked on 16 October 2026: all 114 API smoke requests passed using `main-missions-trusted-v3-all-wire`, with score agreement within 1e-9 and a slowest request of 2.13 seconds. Trusted Fidelity is deployed. Future code changes still require deploying the frontend and Python function together; no deployment configuration changes are needed. See [migration, stale statements and exact hosted recheck commands](docs/TRUSTED_FIDELITY_MIGRATION.md).

Use Node.js 24.x and preferably Python 3.12 to match deployment. The existing Python 3.10 development environment also passes the physics tests:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.lock.txt
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm dev:all
```

Open http://127.0.0.1:3000. The launcher starts Next.js on port 3000 and the Python API on port 8000; Ctrl+C stops both. On Linux/macOS, use `.venv/bin/python` instead. `requirements-deploy.txt` pins runtime packages; `requirements.lock.txt` also includes test tools. Drawing dependencies remain separate.

Next.js proxies `/api/*` to the Python process. Optional `QUANTUM_API_URL` sets another backend address; `SIMULATION_ENABLED=false` pauses computations. See `.env.example`. No secrets are needed. Python reads its process environment rather than Next's `.env.local`.

On Vercel set `ENABLE_EXPERIMENTAL_COREPACK=1` to honor the pinned pnpm version. The browser API base is `NEXT_PUBLIC_API_BASE_URL`, default `/api`. On Vercel leave `QUANTUM_API_URL` unset: vercel.json selects the same-origin Python function. No browser localhost URL or external CORS dependency is used in production.

For local production verification, start `.venv/Scripts/python.exe -m uvicorn api.index:app --host 127.0.0.1 --port 8000`, run `pnpm build`, then `pnpm start`. Reproduce live verification using the commands in the deployment guide. A global leaderboard remains separate work.

## Playing

Complete the six tutorials or choose **Skip Tutorial / Unlock All Levels**. The tutorials retain their three-pane workspace, blank sandboxes, hardware noise controls, QSphere/Bloch views and parameter-only gate inspector.

All main missions share that workspace and drag/drop renderer. The left panel has the objective, the upper-right panel has the circuit and source editor, and the lower-right panel contains Trusted Fidelity, pass/fail, a short status and compact kept-shot fidelity/shot-budget indicators. Use the Dustbin to remove authored gates. The payload is immutable. The number of ancillas is fixed by the mission.

Missions 1–3 require manual closing products. Missions 4–10 generate signed closing products immediately before the player's final H. Inserting editable columns inside the payload permits short check windows; removing occupied columns requires moving their gates first. Invalid propagation, including X/Y at a T/Tdg crossing, turns the connector red and blocks scoring. Main missions permit Clifford checks and H/M readout; arbitrary rotations belong to the tutorials.

The score is **Trusted Fidelity = F_ps · min(1, S_keep / S_min)**. The per-level shot budget S_min is shown beside kept-shot fidelity and shots kept. This is a game design choice using simulation-only full-state fidelity, not a fidelity estimator obtainable from hardware counts alone. Detailed artifacts always report F_ps and S_keep together; their product remains the secondary `correct_shot_yield`. Noise and targets are server-owned. Changing a draft invalidates its displayed result. Scores do not fluctuate with sampled counts. See [mission physics](docs/SCIENTIFIC_REPORT.md) and [reference validation](docs/LEVEL_VALIDATION.md).

Progress is device-local under `quantum-shield-qed-v2`. Tutorial completion and sound preferences survive the redesign. Mission bests use `missionVersion: 3`; previous bests are archived under `quantum-shield.archived-missions-v1` or `v2` and cleared so old-metric scores/stars never masquerade as Trusted Fidelity records. `unlockedThrough` preserves previously earned access; tutorial completion/skip, lesson evidence and sound preferences remain. FS6 results are not persisted as score records, so its next run computes the new metric. Complete Flight School 6 to open Main1, then pass each mission to unlock the next. The explicit tutorial skip still unlocks every mission. Scores store Trusted Fidelity multiplied by 1000. One star means passing; two/three stars mean exceeding the target by 0.025/0.05. Local storage is not a trusted leaderboard.

The [final Trusted Fidelity verification record](docs/TRUSTED_FIDELITY_VERIFICATION.json) records actual local test counts, timings and scope. The [migration guide](docs/TRUSTED_FIDELITY_MIGRATION.md) lists superseded statements, calibration caveats and the exact hosted rerun commands.

## API

| Route | Purpose |
|---|---|
| `GET /api/health` | Installed engine/package versions |
| `GET /api/levels` | Ten authoritative main mission configurations |
| `POST /api/missions/validate` | `{draft}` → dynamic connectors and locked generated closings |
| `POST /api/missions/run` | `{draft}` → compact authoritative outcome |
| `POST /api/missions/compile` | `{levelId, code}` → allowlisted editor draft or source diagnostics |
| `POST /api/tutorial/noise-lab/{compile,run}` | Flight School 1 |
| `POST /api/tutorial/protection-lab/{compile,preview,run}` | Flight School 2 |
| `POST /api/tutorial/timeline/{compile,validate,run,reveal}` | Flight Schools 3–6 |

The editable source is a bounded teaching API, parsed with Python AST and never executed. A separate read-only Qiskit circuit view shows the compiled operations. Requests are limited to 16 KiB; unknown fields, changed registers, collisions, nonterminal measurement and payload edits are rejected. Per-process computation admission returns 429 when busy. Public distributed rate limiting belongs to deployment work.

## Noise, science and submission

The organizer authorized a participant-selected model. **All models are explicitly synthetic**, with parameters and channel placement in [the report](docs/SCIENTIFIC_REPORT.md). FS6 and Main1 have exactly two data qubits and one fixed helper. Main8–10 contain 1/3/5 T or Tdg gates. Local Aer density matrices score every mission, including T circuits; Paulice is restricted to separate Clifford gamma/windowed suggestions and observable benchmarks. RuntimeService is not used to execute circuits or required for setup. Any future RuntimeService adapter must only fetch calibration data.

See [level validation](docs/LEVEL_VALIDATION.md), [core physics guide](docs/CORE_GUIDE.md), [deliverables checklist](docs/DELIVERABLES_AUDIT.md) and [AI provenance](PROVENANCE.md). The best reference scores are finite-family optima, not global guarantees over arbitrary circuits. The game-score search and Paulice's native measurement-parity cost are deliberately reported separately.
